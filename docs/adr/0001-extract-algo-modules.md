# 0001 — 算法模块拆分：算法出壳，入口留单文件

仓库原本是单文件 `audio_mix.c`。随着被测算法家族增长，每新增一个算法都要在同一文件里跨越多个分节改动，注册流程变脆。决定：把被测对象（五个逐样本公式）与参考链路部件（前瞻限幅器）移入 `src/`（`mix_algos.{c,h}`、`limiter.{c,h}`），`audio_mix.c` 留在根目录作为唯一入口，继续承载指标、WAV I/O、合成素材、表格输出与 `main()`。

## Considered Options

- **保持单文件**：无需构建改动，但算法增长时文件与注册点持续膨胀，是本次要解决的问题本身。
- **每算法一个 `.c`**：粒度过细——每个公式只有 20~30 行，共享的语义约定（签名、钳位统计）放在一个模块头里更清晰，注册表也只有一个权威列表。
- **整文件按节模块化**（metrics / wav / synth / util 各自成模块）：这些节长期稳定，拆开只增加文件与接缝，没有解决任何当前痛点；留给真正出现第二消费者时再做。

粒度上选「算法出壳」：`src/` 内只有会持续增长的部分；Makefile 显式登记 `SRCS`（不用 wildcard），新文件漏编在链接期报错。行为契约是纯拆分——所有算法输出、指标数值、CLI 与 WAV 文件名逐比特不变；拆分时以拆分前构建的 stdout 与全部 WAV 哈希为锚点做过逐比特对照，作为验收依据。
